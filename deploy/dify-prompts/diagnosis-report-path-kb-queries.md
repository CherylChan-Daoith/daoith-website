# 诊断报告：路径判定 + 按路径知识检索

> 流程：问诊 Agent 定路径 → Workflow **必返三篇定骨架**（知识点 + 硬约束 + 路径样本）+ **补充检索造差异** → LLM 写 JSON → Code。  
> 只读样本会「同路径报告长得一样」；多样性必须来自档案各题选项 + 补充材料，但仍锁在当前路径内。

---

## 0. 检索硬要求（骨架 + 多样性）

| 优先级 | 材料 | 作用 |
|--------|------|------|
| **必返 ①** | `00-必须知道的知识点`（或《必须知道的知识点》，全篇优先） | 通用知识点、信息报送等——**所有路径共用** |
| **必返 ②** | `15-出报告硬约束与路径要点`（全篇优先） | 硬规则、三大环节、路径写作约束 |
| **必返 ③** | 当前路径一篇方案样本 `20/21/22/23`（或路径 X 关键词）（全篇优先） | **该路径**架构名与写法口径——只学结构，禁止照抄样本画像 |
| **补充 ④（建议必做）** | 按档案召回：问题分篇、实操附件、DAOITH/退税率等 | **拉开同路径不同卖家的差异** |

冲突时：**用户档案 > 必返①②③ > 补充④**。  
**禁止**把其它路径方案样本当主材料。补充只服务**当前路径 + 当前档案**。

### 路径 → 必返方案样本

| report_path | 必返样本文档 |
|-------------|--------------|
| **A** | `20-方案样本-路径A-海外仓-正式报关` |
| **B** | `21-方案样本-路径B-自发货小包` |
| **C** | `22-方案样本-路径C-平台国内仓` |
| **D** | `23-方案样本-路径D-产品无法退免税` |
| **X** | 暂无单独样本文件：用关键词检索「阿里国际站 一达通 自营出口 便捷发货 视同自产 1210 9610」（必返②）；写报告要点以 Workflow 提示词「路径 X」为准 |

### 多样性从哪里来（固定范围内）

同路径下报告仍应「长得不一样」，因为档案不同。写报告时必须让下列维度**改变** `risk` / `plan.details` / `actions` 的取舍与表述（在路径允许的架构集合内）：

- 平台与目的国相关口径（来自知识点 / 问题1）
- 主体（大陆公司/个人/个体户/香港等 → 信息报送、1039 额度等）
- 发货 + 出口组合（同属 A 时，FBA+委托货代 vs 海外仓+0110 侧重点不同）
- 发票（专票 / 普票 / 无票 → 0110 vs 1039 等）
- 产品（普货 / 涉检 / 0退税标识 → 商检、标识1/2）
- 销售额档位（小规模、500万、5000万、1亿等提示）

**禁止**：同一路径下不管档案如何，都复述样本里同一套「标准四段」；**禁止**为追求多样而跳出当前路径去写另一路径架构。

## 1. 问诊 Agent：路径判定规则（内部，勿对用户说出路径字母）

采信已确认的「平台 + 发货方式 + 出口方式 + 产品类型」，**只选中一条**；未命中一律不写、不对照罗列。  
**顺序强制**：① 产品「0 退税率」或「海关备案商标暂未授权」→ **D**（含阿里国际站，禁止再判 X）；② **仅非 D** 且平台=阿里国际站且发货为自营/一达通/市场采购/便捷发货 → **X**；③ 其余再按发货 + 出口选 C → B → A。路径 X **禁止**串写 0退税率/路径D 文案。

| 路径 | 判定条件 |
|------|----------|
| **D** 产品无法退免税（优先） | 产品：0退税率产品（如贵重金属、珠宝玉石、钢材、铝材、玻璃、木材）/ 产品涉及海关备案商标但暂未获得授权；**国际站遇此类仍走 D** |
| **X** 阿里国际站（非 D 时优先于 A/B/C） | 平台：阿里国际站 + 发货自营/一达通/市场采购/便捷发货 + **产品非0退税率、非商标未授权**。**禁止**建议换香港公司作店铺主体；**禁止**香港公司采购再销售链路；**禁止**「0110/1039出口+香港公司」；**禁止**写 0退税率/按路径D |
| **C** 平台国内仓 | 发货：全托管（国内仓）/ 半托管（国内仓）/ 发货到平台国内仓 / 供货SHEIN（国内仓）等，**或** 出口已记「由平台安排出口」 |
| **B** 自发货小包 | 出口：小包快递出口（9610/1210）、小包快递出口（未报关）；**或** 发货为便捷发货 / POP（国内直发）/ 自发货（国内直发）且走小包/清单（**不含**已归 X 的国际站便捷发货）。产品：普货能正常报关出口和退税 / 涉检 |
| **A** 海外仓（默认） | 发货：平台海外仓 / 自发货（海外仓）/ 亚马逊FBA / 半托管（海外仓）/ POP（海外仓发货）/ Shopee海外仓 / FBL海外仓 等。出口：正式报关（0110/9710）/ 正式报关（9810）/ 市场采购（1039）/ 委托货代出口。产品：普货能正常报关出口和退税 / 涉检 |

定路径后调用 `generate_diagnosis_report`，参数至少包含：

- `diagnosis_archive`：完整【诊断档案】
- `report_path`：`A` / `B` / `C` / `D` / `X`（必填；只传字母）
- `user_reply`：用户最后一轮答复（可选）
- `follow_up_changes`：变化点（追问改档时可选）

**禁止**为定路径去检索知识库；**禁止**向用户解释「你是路径 A/X」；Workflow 只展开该路径要点与对应样本。

## 3. 画布（推荐：三路必返 + 一路补充，全部并行）

```text
开始
  ├─→ 模板·知识点query → 知识检索必须知道（必返①）
  ├─→ 模板·硬约束query → 知识检索硬约束（必返②）
  ├─→ Code·样本query(report_path) → 知识检索路径（必返③）
  └─→ 模板·补充query(档案) → 知识检索补充（多样性④）
           ↓ 四路汇合到「模板汇总检索」
  → LLM → Code → 结束
```

「模板汇总检索」输入建议：`must` / `hard` / `path` / `supp` 四个 `result`，Jinja 分栏输出（**不要漏掉 `{{ supp }}`**）：

```text
【必返·必须知道的知识点·全篇优先】
{{ must }}

【必返·出报告硬约束与路径要点·全篇优先】
{{ hard }}

【必返·本路径方案样本·全篇优先】
{{ path }}

【补充·按档案造差异】
{{ supp }}
```

时效：四路并行 ≈ 最慢一路。

### 4.3 知识检索·补充（建议必做 · 造差异）

查询须来自变量。可用 **模板转换**，正文示例：

```text

{{#start.diagnosis_archive#}}
```

或用 **Code** 从档案抽关键词拼 query（更干净），伪逻辑：从 `diagnosis_archive` 取出平台/主体/发货/出口/发票/产品/销售额原文片段，拼成：

```text

```

路径附加（写入同一补充 query 末尾即可）：

| 路径 | 追加关键词 |
|------|------------|
| A | `0110 9810 1039 委托货代 海外仓 信息报送` |
| B | `9610 1210 小包 综试区 无票免征` |
| C | `全托管 平台安排出口 视同内销 国内仓` |
| D | `0退税率 特殊商品标识 视同内销 出口免税` |

## 5. 知识检索勾选库与参数

- 必挂：`合规解决方案必读文件`（须已收录上述 15 / 20 / 21 / 22 / 23 文档）——**硬约束与路径样本都在同一库即可，不必拆库**
- 补充可再挂：实操附件（若独立成库）、海关编码和出口退税率、出口退税法规、DAOITH 跨境库
- 必返①②：Top K **8～12**；补充③：**6～8**
- Rerank 可用；Score 阈值建议先关
- **索引建议**：`15` 与各 `20–23` 尽量整篇或大块入库

### 5.1 同一库里「只读一份文件」怎么做

知识检索节点挂的是**整个库**，默认会混进其它文档片段。要逼近「只读这一篇」，用下面两种方式（可叠加）：

| 做法 | 怎么配 | 效果 |
|------|--------|------|
| **A. 两次检索 + 精确标题 query**（必做） | 两个知识检索节点都只勾选「合规解决方案必读文件」；节点① query 只写硬约束标题；节点② query 只写当前路径样本文件名 | 多数情况下 Top 结果集中在目标篇；仍可能夹杂相近文档 |
| **B. 元数据筛选（推荐，真正锁文档）** | 知识库开启内置元数据 `document_name`（或自定义字段如 `doc_id`）；检索节点 → **元数据筛选 → 手动** → `document_name` **是** / **包含** → 常量填入库中**确切文件名** | 先按文件过滤再向量检索，其它路径样本进不来 |

**B 的手工示例（硬约束节点）**：

- 筛选模式：手动  
- 条件：`document_name` **是**（或 **包含**）`15-出报告硬约束与路径要点.md`（以知识库文档列表里显示的名称为准）

**路径样本节点**：四路条件分支里，每路写死对应文件名，例如路径 C：`22-方案样本-路径C-平台国内仓.md`。

若界面没有「元数据筛选」：至少用做法 A（精确标题 + 高 Top K），并在试跑里确认结果来源文档是否为目标篇。

## 6. LLM USER 模板（必返与补充分栏）

推荐：四路检索先汇入「模板汇总检索」，USER 只插一次汇总 + 档案：

```text
【报告路径·内部】{{#start.report_path#}}（禁止写入 JSON 正文）

【诊断档案】
{{#start.diagnosis_archive#}}

【用户最后答复】
{{#start.user_reply#}}

【变化点（若有）】
{{#start.follow_up_changes#}}

【检索汇总·含必返知识点/硬约束/路径样本 + 补充】
{{#模板汇总检索.output#}}

写作要求：
1. 必返三栏（必须知道的知识点 + 硬约束 + 路径样本）定骨架；样本只学口径与架构名，禁止照抄示例平台/销售额。
2. 补充栏用来区分本案（平台/主体/发货/出口/发票/产品/销售额）；禁止同路径千篇一律。
3. 多样性只能在当前路径允许的架构内；冲突时档案与必返优先。
4. 只输出 version=1 的 JSON。
```

「模板汇总检索」Jinja 必须含四栏（`must` / `hard` / `path` / `supp`），**不要漏 `{{ supp }}`**。
