# 诊断助手：提示词与知识库分层

以后所有调试都按此分层增补，**避免把细则再堆进系统提示词**（提示词过长会显著增加 token 消耗并降低效率）。

## 三层各写什么

| 层级 | 文件 | 只放这些 | 不要放这些 |
|------|------|----------|------------|
| **提示词** | `diagnosis-agent-system.md`（Dify Instruction） | 如何识别客户问题并分类；每类追问逻辑、解答逻辑；解答内容的基本要求；**出报告前必读**《出报告硬约束与路径要点》《必须知道的知识点》 | 报告章节版式、路径 A/B/C 要点、退税四条件全文、架构链路、报送细则 |
| **必读知识库** | `15-出报告硬约束与路径要点.md` | 诊断报告的具体格式要求、章节写法、硬约束、内部路由、路径要点、报告生成的内容要求 | 问诊话术、模式分类 |
| **必读知识库** | `00-必须知道的知识点.md` | 生成诊断报告的核心知识点（退税四条件、四套架构、信息报送、无法退免税处理、销售额分层） | 报告四章版式示例 |
| **参考资料** | 问题1–7分篇、`10–14` 附件、`20–22` 方案样本、其它法规库 | 按用户选项/主题按需检索 | 不要复制进提示词 |

出报告流水线（提示词只点名，细则在必读文件）：通读《出报告硬约束与路径要点》→ 通读《必须知道的知识点》→ 检索对应「问题X+关键词」与命中方案样本 → 按必读文件生成报告。

## 线上粘贴

1. `diagnosis-agent-system.md` → Dify Agent **指令 / Instruction**（纯文本粘贴后发布）
2. `diagnosis-agent-opening.md` → 开场白
3. `diagnosis-agent-kb-instruction.md` → 知识库工具描述 / 检索查询说明
4. `diagnosis-agent-system.full.md` 仅为历史归档，**勿作线上 Instruction**

知识库上传目录：`data/compliance-must-read-md/`（见该目录 README）。
